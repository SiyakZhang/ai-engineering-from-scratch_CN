# 自动化前先设计交接 · 自测

每题先选答案，再展开解析。

## 1. 选择 Claude 工作流模式前，应该先做什么？

- **A** 绘制流程前先选择模型家族
- **B** 绘制真实的当前流程、决策、来源、负责人和例外
- **C** 记录当前缓慢或不一致的步骤前，先定义未来自动化路径
- **D** 根据预期模型调用次数估算 token 成本，再设定工作流范围

<details>
<summary>查看答案与解析</summary>

**答案**　B

当前状态图能揭示未来设计必须保留或改进的实际判断、责任归属和失败路径。

</details>

## 2. 某团队花费数小时核对相互冲突的来源系统。哪种干预最有效？

- **A** 生成冲突报告，以加快审核
- **B** 生成后添加最终验证步骤，但保持来源责任归属不变
- **C** 先重新设计来源流程，再考虑自动化表面症状
- **D** 使用 adaptive agent 判断每处冲突中哪个来源看起来最可信

<details>
<summary>查看答案与解析</summary>

**答案**　C

底层浪费来自来源冲突。自动生成冲突说明只会保留有问题的流程。

</details>

## 3. 审核者交接数据包中应包含什么？

- **A** 打磨后的草稿、评估汇总分数和模型置信度估计
- **B** 完整对话与工具轨迹，让审核者自行重建决策
- **C** 推荐决策和引用，为节省审核时间而省略被拒绝选项
- **D** 所需决策、证据、来源版本、检查、不确定性、可选操作和备用路径

<details>
<summary>查看答案与解析</summary>

**答案**　D

结构化数据包让审核者无需重建工作流，就能验证并做出决策。

</details>

## 4. 为什么外部操作的重试必须谨慎设计？

- **A** 重复执行非幂等操作可能导致消息、扣款或其他效果重复
- **B** 检查点可以证明上一次外部操作失败，因此重试一定安全
- **C** 重试生成可能改变参数，因此每次重复输出都应丢弃
- **D** 只有带写权限的工具调用需要限制重试；消息随时可以重发

<details>
<summary>查看答案与解析</summary>

**答案**　A

生成重试通常没有危害，但外部操作需要幂等性和有记录的完成状态。

</details>

## 5. 某工作流自动发布管理层简报，但批准责任归属不清。最好的修复是什么？

- **A** 把低置信度简报路由给普通审核者，其他输出直接发布
- **B** 发布前定义步骤负责人、发布门槛、决策数据包和备用路径
- **C** 添加更严格的 rubric，让模型自行判断简报何时可以发布
- **D** 要求两个独立模型审核者在自动发布前达成一致

<details>
<summary>查看答案与解析</summary>

**答案**　B

主要缺陷是工作流没有明确决策权和交接。单独提高生成质量无法解决。

</details>

## 6. 有限生产发布前，什么证据最可靠？

- **A** 内部试点的用户采用率很高，但尚未测量修正和审核成本
- **B** 使用最常见案例和当前生产来源完成了一次成功演示
- **C** 覆盖正常和例外案例的影子模式结果、实测门槛、审核投入，以及准备就绪的事件负责人
- **D** 供应商基准测试，加上每个确定性工作流组件的单元测试

<details>
<summary>查看答案与解析</summary>

**答案**　C

影子模式在不授予操作决策权的情况下测试真实工作流，并暴露例外与运营成本。

</details>
