# 验证主张，而非置信度 · 自测

每题先选答案，再展开解析。

## 1. 报告中每项主张旁边都有引用。验证还必须确认什么？

- **A** 每个来源都具有权威性，并支持确切主张
- **B** 即使多项主张共享证据，每个事实句子也各有一处引用
- **C** 引用格式一致，而且所有链接都能在不重定向的情况下打开
- **D** 每个链接页面都有相同的发布日期

<details>
<summary>查看答案与解析</summary>

**答案**　A

存在引用不能证明权威性、完整性或蕴含关系。证据必须支持具体主张。

</details>

## 2. 应该用哪种评估器检查返回的 JSON 能否解析并包含必需字段？

- **A** 基于模型的 schema 评分器
- **B** 确定性 parser 和 schema 检查
- **C** 要求生成模型确认自己的回复符合 schema
- **D** 由人工审核者在使用前按清单检查每个返回对象

<details>
<summary>查看答案与解析</summary>

**答案**　B

精确结构属性应通过程序检查，因为结果可重复且没有歧义。

</details>

## 3. 回复流畅地回答了一项在所提供来源快照之后发布的政策。哪种修复最能针对知识限制？

- **A** 增加输出长度，让模型解释其记忆内容
- **B** 把精致措辞当作模型已经知道该政策的证据
- **C** 把当前获批政策加入证据，并重新运行主张支持检查
- **D** 提高置信度门槛，再要求生成一次相同答案

<details>
<summary>查看答案与解析</summary>

**答案**　C

知识缺口需要当前权威上下文和验证。泛泛重试不会改变工作流可用的信息。

</details>

## 4. 评估汇总分数为 95%，但高影响例外案例通过率只有 40%。应该用什么控制部署？

- **A** 只按例外案例预期流量占比计算的加权平均值
- **B** 正常案例分数，加上全面部署后监控例外的计划
- **C** 只要例外案例占流量不到 5%，就采用汇总分数
- **D** 风险群体的失败情况和必需发布门槛

<details>
<summary>查看答案与解析</summary>

**答案**　D

必须按后果对表现分组。高平均分不能掩盖关键案例上不可接受的行为。

</details>

## 5. 回复称培训导致退货减少，但来源只表明培训先发生。这属于什么缺陷？

- **A** 从相关性越界推断到因果关系
- **B** 完整性失败，因为回复没有引用时间线中的每个事件
- **C** 受众适配失败，因为因果语言只能用于技术报告
- **D** 来源追踪失败，因为引用无法表示时间顺序

<details>
<summary>查看答案与解析</summary>

**答案**　A

结论强于证据，因此即使两个事件都真实存在，主张与证据的关系仍不成立。

</details>

## 6. 发生重大生产失败后，最可靠的应对方式是什么？

- **A** 不定位失败层级，直接提高模型置信度门槛
- **B** 添加长期评估案例，并修复相关标准、来源、prompt 或工作流控制
- **C** 修正受影响的输出，并在本周为类似请求增加人工审核步骤
- **D** 因为生产输入不可控，所以从汇总报告中排除失败示例

<details>
<summary>查看答案与解析</summary>

**答案**　B

把失败纳入后续测试和系统设计，才能闭环并防止复发。

</details>
