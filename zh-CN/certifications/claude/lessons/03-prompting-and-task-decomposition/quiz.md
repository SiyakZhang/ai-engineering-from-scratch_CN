# 把请求变成可测试的合约 · 自测

每题先选答案，再展开解析。

## 1. 优化复杂 prompt 的措辞前，应该先定义什么？

- **A** 与代表性输入和失败条件关联的可观察成功标准
- **B** 只定义所需输出格式和最大长度，不定义正确性
- **C** 用于增强自信语气和领域词汇的详细专家人设
- **D** 生产工作流可用的模型家族和最大上下文预算

<details>
<summary>查看答案与解析</summary>

**答案**　A

没有可观察标准，就无法评估 prompt 修改；流畅的失败也可能看起来像成功。

</details>

## 2. 某份报告提取内容准确，但建议缺乏证据支持。最有用的拆解边界在哪里？

- **A** 检索完成后，把提取和分析合并
- **B** 在提取与分析之间设置证据门槛
- **C** 在每个段落之间拆分，让每节都单独调用一次模型
- **D** 在分析与格式化之间拆分，但此时建议已经被接受

<details>
<summary>查看答案与解析</summary>

**答案**　B

在解释前核验提取出的证据，可以定位失败，并防止缺乏支持的分析流向下游。

</details>

## 3. 对分类任务而言，什么样的 few-shot 示例最有用？

- **A** 展示一个典型正面示例及其标签
- **B** 匹配平均输入长度，并采用模型偏好的回复风格
- **C** 展示一个重要边界或模糊案例及其正确标签
- **D** 用不同措辞重复一个先前正确的示例，但仍使用同一个简单区分

<details>
<summary>查看答案与解析</summary>

**答案**　C

边界示例会教模型必须应用的区分方式；重复简单示例几乎不会增加有效信号。

</details>

## 4. 提供的两个来源相互冲突。prompt 应规定什么？

- **A** 只要两个来源都不能丢弃，就合并两项主张的流程
- **B** 只报告选中来源并隐藏分歧的引用规则
- **C** 始终选择最近修改文档的新旧程度优先规则
- **D** 权威顺序和冲突报告行为

<details>
<summary>查看答案与解析</summary>

**答案**　D

来源层级把权威性与新旧程度分开，并告诉 Claude 如何暴露未解决的冲突。

</details>

## 5. 反复修改 prompt 仍未解决政策例外缺失的问题。下一步最好怎么做？

- **A** 诊断权威来源是缺失了，还是被埋在上下文中
- **B** 添加明确的准确性提醒，并要求每项政策主张都给出置信度分数
- **C** 减少约束数量，让模型可以更自由地推断例外
- **D** 检查所提供的证据与上下文位置前，先升级到更大的模型

<details>
<summary>查看答案与解析</summary>

**答案**　A

失败可能发生在来源层或上下文层。改变措辞无法可靠找回不可用的证据。

</details>

## 6. 哪条 prompt 指令能建立最安全的不确定性处理行为？

- **A** 任何请求字段缺少直接证据时，都返回空回复
- **B** 说明哪些内容尚未证实、指出缺失来源，并避免无证据推断
- **C** 给出最可能的完整答案，并标记低置信度值供日后审核
- **D** 根据相邻证据估算缺失值，但将估算与有来源的事实分开

<details>
<summary>查看答案与解析</summary>

**答案**　B

设计好的弃答会让证据缺口保持可见，避免流畅措辞把不确定性变成事实。

</details>
