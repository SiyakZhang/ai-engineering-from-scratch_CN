# 端到端架构与价值取舍 · 自测

每题先选答案，再展开解析。

## 1. 一个流程的步骤稳定、明确，并有严格的审计要求。默认采用哪种模式最合理？

- **A** 启用工具的单个 prompt
- **B** 规划器—执行器 agent 组合
- **C** 确定性工作流
- **D** 有边界的 agent

<details>
<summary>查看答案与解析</summary>

**答案**　C

步骤明确且有审计需求时，更适合由代码控制状态转换、收窄权限并明确恢复行为。只有自适应路径选择确实属于需求时，使用 agent 才合理。

</details>

## 2. 什么情况下最适合采用多 agent 设计？

- **A** 让多个冗余 agent 独立投票决定每项输出时
- **B** agent 框架无需额外应用代码就能支持交接和并行执行时
- **C** 任务分为明确阶段，每个阶段都能使用专用 prompt 和专用工具集时
- **D** 上下文隔离、独立审核或并行工作能带来可衡量的结果改善时

<details>
<summary>查看答案与解析</summary>

**答案**　D

多个 agent 会增加协调成本和交接风险。只有隔离、独立审核、并行执行或专业化能带来可衡量的收益，才值得承担这些复杂度。

</details>

## 3. 哪项控制措施应该在模型之外强制执行？

- **A** 请求的退款是否超过调用方的授权额度
- **B** 根据现有证据，某项条款是否会带来重大业务风险
- **C** 摘要是否保留了源材料中影响决策的细微差别
- **D** 草稿是否足够有说服力

<details>
<summary>查看答案与解析</summary>

**答案**　A

授权额度是基于可信身份和交易数据的稳定判断条件，必须由代码强制执行。语义判断可以使用 Claude，并配合评估和审核。

</details>

## 4. 为什么每 token 最便宜的模型，落实到每个成功任务时反而可能更贵？

- **A** 较低的单价总会降低任务成本
- **B** 更高的重试率和人工审核率可能抵消较低的调用价格
- **C** 它的 token 价格会改变昂贵或高影响工具调用的授权边界
- **D** 它的能力级别较低，因此每项工具操作都必须由人工审核人确认

<details>
<summary>查看答案与解析</summary>

**答案**　B

架构经济性包括重试、工具调用、审核人力和纠错成本。单价较低并不保证每个被接受结果的预期成本更低。

</details>

## 5. 合同处理流水线返回了文笔精致的修订稿，其中却包含没有依据的结论。哪项改动最能解决这一结构性故障？

- **A** 检索排名最高的条款，一次生成完整修订稿，并保留置信度评分最高的版本
- **B** 对每份完成的修订稿运行第二个验证 prompt，验证器未报告无依据主张时就接受
- **C** 通过明确契约分开检索、条款分析、证据审核、修订稿生成和审批
- **D** 把完整合同和政策库加入一个更长的 prompt，再要求返回的修订稿提供引用

<details>
<summary>查看答案与解析</summary>

**答案**　C

故障源于职责被压缩在一起，而且缺少可追溯信息。通过契约拆解可以定位错误，并防止生成步骤绕过证据审核。

</details>

## 6. 反馈记录应该包含什么，才能指导架构变更？

- **A** 最终答案、引用的证据，以及模型为每项结论报告的置信度
- **B** 附在最终响应上的任务级评分、审核人身份和时间戳
- **C** 已完成模型执行轨迹的 token 用量、延迟、重试次数和总成本
- **D** 输入类别、版本、证据、执行轨迹、验证、人工编辑和下游结果

<details>
<summary>查看答案与解析</summary>

**答案**　D

有用的反馈闭环会把结果与产生它的系统状态和执行轨迹联系起来。这些证据能区分 prompt、检索、工具、路由和范围故障。

</details>
