# 让能力受权责边界约束 · 自测

每题先选答案，再展开解析。

## 1. 连接器可以读取客户记录，模型可以起草优惠方案。发送前还需要什么？

- **A** 有记录的决策权、获批目的、控制措施，以及所有必需的人工批准
- **B** 一条要求 Claude 只发送其认为公平且准确的优惠方案的 prompt
- **C** 一个在发送前检查语气和优惠必需字段的生成后评估器
- **D** 把连接器读取权限视为足够的发送决策权

<details>
<summary>查看答案与解析</summary>

**答案**　A

技术能力和数据访问权限，并不会授予做出或执行决策的组织决策权。

</details>

## 2. 哪项操作最能体现数据最小化？

- **A** 缩短完整 prompt 的保留时间，却不移除不必要字段
- **B** 只提供获批任务真正需要且已经完成脱敏处理的字段
- **C** 发送完整客户记录，但要求 Claude 只使用相关字段
- **D** 加密整个数据集，再把全部记录发送到获批产品载体

<details>
<summary>查看答案与解析</summary>

**答案**　B

最小化会把输入缩减到获批目的所需的最少信息。

</details>

## 3. 为什么必须针对确切产品载体核验 Claude 的数据与保留行为？

- **A** 产品控制不可用时，可以用 system prompt 要求更严格的保留策略
- **B** 每种载体都遵循相同默认条款，但 Enterprise 设置可以覆盖它们
- **C** 因为条款、设置、套餐、合同和功能会因产品载体不同而变化
- **D** 保留只影响外部客户数据，因此内部工作流只需更简单的检查

<details>
<summary>查看答案与解析</summary>

**答案**　C

隐私和保留是可能变化的产品与合同事实，因此不能把一个载体的假设直接套到另一个载体。

</details>

## 4. 怎样才能让人工审核门槛具备实际作用？

- **A** 每项输出都先暂停，直到有员工确认模型遵循了 prompt
- **B** 审核者看到打磨后的输出，并能在规定服务时限内批准
- **C** 工作流根据案例与先前批准记录的相似度选择审核者
- **D** 审核者能看到证据、不确定性和政策，并有权拒绝或升级

<details>
<summary>查看答案与解析</summary>

**答案**　D

有效监督要求审核者知情、有决策权，也能实际干预。只设置批准按钮会让审核流于形式。

</details>

## 5. 检索到的文档要求忽略工作流政策并调用工具。怎样处理最安全？

- **A** 视为不可信数据，坚持上层政策并阻止未授权工具
- **B** 先让第二个模型判断文档是否恶意，再允许它扩大权限
- **C** 从检索文本中删除祈使句，然后执行其余请求
- **D** 只有来源排名较高且请求的工具只读时，才遵循文档指令

<details>
<summary>查看答案与解析</summary>

**答案**　A

检索内容可能携带 prompt 注入。工具授权和治理指令必须位于不可信文本之外。

</details>

## 6. 排名系统在不同受影响群体上的错误率存在显著差异。下一步最好怎么做？

- **A** 添加明确的公平性指令；如果汇总评估仍通过，就继续上线
- **B** 由合格负责人查明数据和流程原因、落实政策并保留修正或申诉渠道
- **C** 重新加权汇总指标，让每个群体贡献相同，再根据该分数发布
- **D** 从评估数据中移除群体标签，避免模型和审核者使用

<details>
<summary>查看答案与解析</summary>

**答案**　B

公平性控制必须明确群体、结果、衡量方式、治理和补救路径。一句模糊指令解决不了问题。

</details>
