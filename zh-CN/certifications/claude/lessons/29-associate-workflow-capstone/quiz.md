# 交付一周的完整工作流，别只打磨 prompt · 自测

每题先选答案，再展开解析。

## 1. 综合项目的核心交付物是什么？

- **A** 一个精心润色的 prompt，直接根据已批准的来源归档起草每周简报
- **B** 背下模型、上下文限制、产品形态和功能可用性的比较
- **C** 一个自动发布服务，从周期性报告流程中移除人工审批
- **D** 一套包含来源、验证、权限、移交和恢复的受治理决策工作流

<details>
<summary>查看答案与解析</summary>

**答案**　D

综合项目以可观察、可审核的工作流为主线，覆盖 Associate 路线要求的各项能力。

</details>

## 2. 为什么要冻结每周来源快照？

- **A** 让生成和审核引用同一个带版本的证据边界
- **B** 消除来源责任归属的需要，因为版本管理会自动确立权威性
- **C** 用一个每周归档链接取代各项主张引用
- **D** 保证每个来源在有记录的截止时间后永远正确

<details>
<summary>查看答案与解析</summary>

**答案**　A

快照让运行可以复现，并暴露需要单独进行差异审核的变化。

</details>

## 3. 综合项目的哪项属性应该由确定性 Python 校验？

- **A** 管理层是否喜欢简报的语气、叙事方式、用词和细节程度
- **B** 每项主张的来源 ID 是否存在于本次运行使用的版本化登记册中
- **C** 指定审核人是否具备足够的能力和决策权限
- **D** 来源政策是否为受影响人群带来伦理上充分的结果

<details>
<summary>查看答案与解析</summary>

**答案**　B

引用完整性精确且可重复。伦理充分性和审核人资质需要组织判断。

</details>

## 4. 主管批准简报后，一个已签署来源发生了变化。应该怎么做？

- **A** 要求模型忽略变化字段，让获批草稿仍能根据之前的 prompt 复现
- **B** 发布获批简报，并记录来源变化，留到下一个每周报告周期处理
- **C** 使发布门禁失效，将新来源与获批快照比较，并审核差异
- **D** 删除之前的快照并重建来源登记册，使审核人只看到最新证据

<details>
<summary>查看答案与解析</summary>

**答案**　C

审批适用于特定证据快照。重大变更必须在发布前经过评估。

</details>

## 5. 工作流反复漏掉一个区域例外。哪种应对最可靠？

- **A** 暂停该区域，直到其输入符合其他区域使用的标准报告格式，并补充说明
- **B** 加强置信度措辞，使审核人能够区分结论和区域例外
- **C** 继续在每周人工审核期间手动纠正该区域例外
- **D** 把故障加入评估集，并修复来源、prompt 或覆盖控制

<details>
<summary>查看答案与解析</summary>

**答案**　D

应保留该案例并修复系统，把它纳入反馈闭环，防止同类问题再次发生。

</details>

## 6. 综合项目何时可以进行有限发布？

- **A** 正常和故障测试通过、阻塞项解决、人工权限和回退有效，并且当前产品事实已经核实后
- **B** 每个工作流阶段都实现自动化、输入差异被消除，而且发布不再依赖人工干预或明确批准时
- **C** 一次端到端演示通过，而且团队记录了所有剩余缺陷供试点期间监控后
- **D** 选择能力最强的模型，而且其基准结果超过普通工作流案例的基线时

<details>
<summary>查看答案与解析</summary>

**答案**　A

就绪需要质量、治理、运维、恢复和当前产品配置各方面的证据。

</details>
