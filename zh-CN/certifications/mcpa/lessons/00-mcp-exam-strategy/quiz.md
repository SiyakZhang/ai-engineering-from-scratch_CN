## 1. MCPA 蓝图中某个领域的权重，最直接告诉考生什么？

- **A** 五个领域在官方指南中的排列顺序
- **B** 平均而言，考试中来自该领域的内容占比
- **C** 考生必须在该领域单独达到的最低分数
- **D** 报考前必须完成的官方培训小时数

<details>
<summary>查看答案与解析</summary>

**答案**　B

官方公布的领域权重表示该领域在蓝图中的占比，也就是它平均占考试内容的比例；它不规定阅读顺序、必修时数或单领域最低分数。

</details>

## 2. 哪两个领域合计占 MCPA 蓝图的比例最高？

- **A** MCP 基础与架构和组件，即两个基础领域
- **B** 架构和组件与用例和生态，即两个中等权重领域
- **C** 交互和执行与安全和治理，即两个最高权重领域
- **D** 用例和生态与 MCP 基础，即两个面向采用的领域

<details>
<summary>查看答案与解析</summary>

**答案**　C

交互和执行占 26%，安全和治理占 24%，合计正好是蓝图的一半，因此应为这两个领域分配最多的学习时间。

</details>

## 3. MCPA 认证页面与 Linux Foundation 自己的发布新闻稿对某项考试事实说法不一。这项事实是什么，本课程采用哪个来源？

- **A** 包含的重考次数
- **B** 证书有效期
- **C** 考试费用
- **D** 考试时长

<details>
<summary>查看答案与解析</summary>

**答案**　D

认证页面写考试时长为 90 分钟，新闻稿写 120 分钟。本课程采用更直接面向考试的认证页面，同时明确记录冲突，而不是悄悄选择一个数字。

</details>

## 4. 一道练习题声称，客户端必须先调用 initialize，2026-07-28 版服务器才会接受其他请求。准备充分的考生应如何判断？

- **A** 这是旧版协议干扰项
- **B** 它只对较旧的 MCP 服务器为真
- **C** 它只是 stdio 特有的细节
- **D** 它仍是当前版本的真实要求

<details>
<summary>查看答案与解析</summary>

**答案**　A

2026-07-28 版本彻底移除了 initialize 握手和协议会话。现在每个请求都在元数据中携带自己的协议版本与能力，不依赖之前的握手。

</details>

## 5. 一名考生在权重为 16% 的 MCP 基础领域得分 100%，其他领域均为 0%。为什么加权备考程度比简单的五领域平均值更有用？

- **A** 它会把每个领域的分数向上取整，让考生看起来始终准备充分
- **B** 它给出接近 16% 的备考程度，而不是具有误导性的 20% 简单平均值
- **C** 它把五个领域替换成一个统一的通过或失败标记
- **D** 它会在计算最终结果前丢弃最弱领域的分数

<details>
<summary>查看答案与解析</summary>

**答案**　B

简单平均值因五个领域中有一个满分而得到 20%，但加权估算会反映已掌握领域只占考试的 16%，因此更诚实地呈现整体备考程度。

</details>

## 6. 34 课路线中，JSON-RPC 与 Meta 等少数课程同时标记两个领域。这反映了路线的什么特点？

- **A** 这些课程可以选择跳过
- **B** 这些课程应获得双倍学习时间
- **C** 同一个概念会从两个领域的角度被考查
- **D** 课程编号存在需要修复的错误

<details>
<summary>查看答案与解析</summary>

**答案**　C

一课可能确实位于两个领域的交叉点，例如消息信封既是核心概念，也是架构组成。因此路线会同时标记两个领域，而不是强行任选其一。

</details>
