## 1. 某平台团队目前为 6 个内部应用与 9 个外部系统之间的每一种组合分别维护手写连接器。随着应用和系统不断增加，连接器数量也持续增长。管理层询问，采用 MCP 这类用于上下文与工具访问的统一协议是否有帮助。最有力的理由是什么？

- **A** MCP 能把兼容应用与系统之间自定义连接器的乘法式增长变为加法式增长
- **B** MCP 不再需要应用与其访问的系统之间执行任何授权或同意步骤
- **C** MCP 保证每个外部系统都公开完全相同的数据，无论系统实际存储什么
- **D** MCP 让团队从此不必决定应用内部具体使用哪一种大语言模型

<details>
<summary>查看答案与解析</summary>

**答案**　A

MCP 对 AI 应用与外部系统之间的集成接口进行标准化，使集成数量从大致等于应用数乘以系统数，变为大致等于两者之和。它不会选择模型、保证数据相同，也不会取消授权要求。

</details>

## 2. 一名刚加入团队的支持工程师告诉同事：每次 MCP 交互都必须先发送 initialize 请求，服务器才会接受其他调用。该同事正在查阅 2026-07-28 版规范，应当如何回应？

- **A** 表示赞同，因为 initialize 仍会创建共享会话，后续每个请求都依赖该会话
- **B** 说明 initialize 和会话已被移除，因为现在每个请求都会自行携带版本与能力信息
- **C** 表示赞同，但指出如今只有远程 HTTP 服务器仍要求完整的 initialize 握手
- **D** 说明 initialize 现在完全可选，但仍会返回供后续调用使用的会话 ID

<details>
<summary>查看答案与解析</summary>

**答案**　B

2026-07-28 版移除了 initialize 请求、notifications/initialized 以及协议会话。现在每个请求都在自己的逐请求元数据中携带 protocolVersion、clientCapabilities 等字段，因此不再需要握手或会话。

</details>

## 3. 某团队正在判断其客户端是否仍可安全依赖 roots 功能。一名工程师称该功能已在 2026-07-28 版中移除，必须立即删除；另一名工程师查看了弃用功能登记表。对于 roots 这类已弃用功能，登记表实际说明了什么？

- **A** 没有任何文档，团队只能根据论坛帖子猜测其状态
- **B** 状态为 Active，属于完全现行功能，未来多年都无需改动
- **C** 状态为 Deprecated，但仍可用，并提供迁移路径和最早移除日期
- **D** 状态已是 Removed，因此任何调用它的客户端代码都会立即失败

<details>
<summary>查看答案与解析</summary>

**答案**　C

在功能生命周期中，已弃用功能仍有规范且保持可用，同时必须提供迁移路径，并在可能移除前保留最短过渡期。把“已弃用”误当成“已移除”，会导致团队过早删除仍能工作的集成。

</details>

## 4. 运维人员将一台远程 MCP 服务器从单副本扩容为负载均衡器后的三个副本，且未启用粘性路由。某工具把每个客户端的累计值保存在进程内存中，此后各次调用返回的总数开始来回跳变。根本原因是什么？

- **A** 负载均衡器改写了 JSON-RPC ID，导致结果匹配到错误调用
- **B** 客户端在第一次调用后不再声明能力，因此后续副本忽略了它
- **C** 每个副本分别协商协议版本，因此对结果格式意见不一
- **D** 累计值只存在某个副本的内存中，没见过该值的副本无法继续累计

<details>
<summary>查看答案与解析</summary>

**答案**　D

在无状态核心中，每个请求都必须仅凭自身内容及明确指定的句柄得到处理。因此，跨调用状态应放在由共享存储支撑、服务器签发的句柄之后，而不能留在单个副本的内存里。请求一旦分散到不同副本，未创建这份隐式客户端状态的副本就看不到它，于是出现了运维人员观察到的数值漂移。

</details>

## 5. 一名曾开发 JSON-RPC 批处理客户端的开发者，希望向 2026-07-28 版服务器发送一个包含多个工具调用的 HTTP POST 请求体，以减少往返次数。预期会发生什么？

- **A** 请求会被拒绝，因为批处理已移除，现在每个 POST 请求体只能携带一个请求
- **B** 服务器只处理数组中的第一个调用，并悄悄丢弃其余调用
- **C** 服务器会接受整个批次，并在一个大型结果数组中逐一回答所有调用
- **D** 服务器会将额外调用排队，并在数分钟内逐个回答

<details>
<summary>查看答案与解析</summary>

**答案**　A

MCP 已在 2025-06-18 版中移除 JSON-RPC 批处理，2026-07-28 版仍不支持。因此，Streamable HTTP 的 POST 请求体必须只包含一个 JSON-RPC 请求或通知，不能包含由多个请求组成的数组。

</details>

## 6. 一名新同事询问 host 与其使用的客户端和服务器之间是什么关系。哪项描述符合 2026-07-28 版架构？

<details>
<summary>查看答案与解析</summary>

**答案**　B

host 应用会为每个服务器连接嵌入一个客户端实例。因此，每个客户端都与一台服务器保持一对一关系，而 host 负责协调全部连接，并为模型汇总结果。

</details>

## 7. 某供应商建议公司为每个合作伙伴系统分别开发定制 SDK，而不要采用 MCP，理由是统一协议会增加不必要的抽象。从互操作性角度看，最有力的反驳是什么？

- **A** 统一协议意味着合作伙伴系统完全不必再发布任何文档
- **B** 统一协议意味着以后再也不必协商协议版本
- **C** 统一协议让任何兼容客户端无需系统专用胶水代码即可使用任何兼容服务器
- **D** 统一协议据称能保证每个合作伙伴系统都获得完全相同的性能

<details>
<summary>查看答案与解析</summary>

**答案**　C

开放统一协议的价值在于，发现与能力协商以数据而非代码表示，因此一次构建的客户端可以与任何符合规范的服务器协作。它不会拉齐性能、取消版本协商，也不能取代文档。

</details>

## 8. 架构评审正在列举采用 MCP 这类开放统一协议、而不是自定义点对点集成的实际优势。哪两项说法正确？请选择两项。

- **B** 每台服务器都会自动获得与其他已连接服务器完全相同的用户界面

<details>

**答案**　C、D

对应用与系统之间的传输协议进行标准化后，客户端无需定制胶水代码即可发现和使用任何兼容服务器，也让集成数量从乘法式增长变为加法式增长。MCP 不会统一用户界面，也不会替 host 选择运行的模型。

</details>

## 9. 工程师阅读 2026-07-28 版变更日志时，看到一条包含特定 SEP 编号和简短标题的记录。要判断某功能目前是否适合依赖，应当如何使用这条记录？

- **B** 只看变更日志标题就足够了，因为 SEP 编号只是历史花絮
- **C** 假定每条变更日志都描述了现已移除的功能

</details>

## 10. 某团队正在记录其 MCP 服务器为何让每个请求都自包含，而不依赖连接状态。这种无状态设计会带来哪两项结果？请选择两项。

- **A** 负载均衡器后的任何副本都能正确回答任意传入请求
- **B** 服务器可以省略 resultType，因为连接已确定应返回哪类答案
- **C** 请求中断后重试时，可将其路由到另一服务器实例而不影响正确性

<details>
<summary>查看答案与解析</summary>

**答案**　A、C

由于同一连接上的前一个请求不能向后续请求隐式传递信息，任何副本都能处理任何请求，重试也可安全地路由到任意副本。这正是无状态核心不要求负载均衡器使用粘性路由的原因。

</details>

## 11. 客户端对某工具发送 tools/call 请求。该工具的描述表明它可能向用户追问，但客户端请求并未声明 elicitation 能力。服务器应当怎么做？

- **A** 返回 MissingRequiredClientCapability 错误，并指出客户端必须声明的能力
- **B** 悄悄把整个工具调用降级为更安全的只读版本
- **C** 无限期缓存请求，直到客户端最终自行声明缺少的能力
- **D** 仍然继续执行，因为能力声明只是无关紧要的形式

<details>
<summary>查看答案与解析</summary>

**答案**　A

服务器不能依赖客户端未在当前请求中声明的能力。因此，当服务器需要 elicitation 而请求缺少该能力时，应返回 MissingRequiredClientCapability 错误，并在错误数据中列出所需能力。

</details>

## 12. 某工具定义了描述结构化发票对象的 outputSchema。客户端调用该工具后，收到的 structuredContent 与此 schema 不匹配。这说明服务器实现存在什么问题？

- **A** 客户端一定在原始调用中发送了格式错误的 inputSchema
- **B** 服务器违反了自己的契约，因为 structuredContent 必须符合已声明的 outputSchema
- **C** 什么也不说明，因为 outputSchema 只是装饰，从不与实际结果核对

</details>

## 13. 清单审查人员看到一个工具定义，其 name 为 get_forecast，title 为 Get 7-Day Forecast。客户端调用该工具时，必须把哪个字段作为 params.name 发送？另一个字段有什么用途？

- **C** 把 name 放入 params.name，因为 name 是程序标识符，title 用于显示

</details>

## 14. 在模型交互流程中，host 即将允许模型调用一个标注为破坏性的工具。host 的确认步骤应放在流程中的哪个位置？

</details>

## 15. 某平台团队运行两台 MCP 服务器：一台通过本地 stdio 提供文件系统访问，另一台通过远程 Streamable HTTP 集成 SaaS。审查人员称，host 在工具注册表中以相同方式对待二者，所以两台服务器共享同一信任边界。应当如何纠正？

- **A** 信任边界随进程和网络边界划分，因此两台服务器属于不同的信任域
- **B** 信任边界完全取决于服务器在 discover 结果中声明了哪些能力
- **C** 只要两台服务器公开的工具名称不同，它们就共享同一信任边界
- **D** 只有远程 HTTP 服务器存在真正的信任边界，因为本地子进程天然可信

<details>
<summary>查看答案与解析</summary>

**答案**　A

信任域取决于进程与网络边界，而不是 host 如何列出工具。因此，即使 host 把本地 stdio 子进程和远程 HTTP 服务汇总到同一注册表，它们仍属于不同信任域。名称和已声明能力不会重划该边界。

</details>

## 16. 客户端正在判断使用服务器前何时必须调用 server/discover。关于发现机制，哪两项说法正确？请选择两项。

- **A** 如果服务器只公开一个简单工具，就可以完全不实现 server/discover
- **B** 客户端可以不调用 server/discover，直接发送请求并处理版本错误
- **C** 在允许发送任何其他类型的请求前，服务器必须先返回 DiscoverResult
- **D** discover 返回的 instructions 字段是给模型的自然语言指引，而不是机器校验的契约

<details>
<summary>查看答案与解析</summary>

**答案**　B、D

发现对客户端是可选的，但服务器必须实现；DiscoverResult 的 instructions 字段是面向模型的描述性指引，不是强制执行的契约。请求顺序并不要求先运行 discover，服务器也不能因为工具较少就跳过实现。

</details>

## 17. 某工具的 inputSchema 完全没有 $schema 关键字，而客户端团队的校验库默认使用较旧的 JSON Schema 草案。客户端应采用哪种方言来校验参数？

- **A** 采用校验库的默认方言，因为 MCP 对此不作规定
- **B** 采用 JSON Schema 2020-12，因为缺少 $schema 时 MCP 默认使用该方言
- **C** 采用 Draft-04，因为它仍是各类库中部署最广的 JSON Schema 方言
- **D** 采用 Draft-07，因为大多数早期 MCP 服务器都基于该草案编写

<details>
<summary>查看答案与解析</summary>

**答案**　B

MCP schema 在没有 $schema 关键字时默认采用 JSON Schema 2020-12 方言。因此，校验器必须应用 2020-12 语义，而不是库自身的默认值或旧草案。需要其他方言的 schema 必须通过 $schema 显式声明。

</details>

## 18. host 每轮都会为模型重新构建工具列表，但列表中的工具顺序会根据 host 代码中的字典迭代顺序随机变化。一名同事认为这无关紧要。为什么它其实是个问题？

</details>

## 20. 某 MCP 服务器通过 file:// 资源 URI 公开内部文档。安全审查人员担心，攻击者可构造 file:///etc/passwd 之类的 URI，越出预期文档目录。符合规范的服务器必须怎么做？

- **C** 完全拒绝 file://，因为 2026-07-28 版只允许 https:// 和 git:// 资源 URI

<details>
<summary>查看答案与解析</summary>

**答案**　A

资源规范要求服务器校验每个资源 URI，并清理文件路径以防目录遍历攻击。file:// URI 未必映射到真实文件系统；但若确实映射，服务器必须在路径接触磁盘前完成检查，而不能信任调用方或传输层。

</details>

## 21. 客户端针对真实存在的 prompt 名称调用 prompts/get，却遗漏了该 prompt 声明为必填的参数。服务器应返回什么？
