# 审查者 Agent：把构建者和打分者分开 · 自测

每题先选答案，再展开解析。

## 1. 为什么构建者无法可靠地给自己的工作打分？

- **A** 验收是必要但不充分的；问题契合度、范围纪律、记录在案的假设和交接就绪度，需要一个有不同输入的不同角色
- **B** 模型拒绝自我评分
- **C** 它丢失了认证
- **D** 它会耗尽 token

<details>
<summary>查看答案与解析</summary>

**答案**　A

构建者与审查者之间的鸿沟正是可靠性所在；验收只能证明一个更弱的版本。

</details>

## 2. 下列哪一个不是五个评分标准维度之一？

- **A** 验证质量（Verification quality）
- **B** 范围纪律（Scope discipline）
- **C** 推理延迟（Inference latency）
- **D** 问题契合度（Problem fit）

<details>
<summary>查看答案与解析</summary>

**答案**　C

这五个是问题契合度、范围纪律、假设、验证质量、交接就绪度。

</details>

## 3. 角色分离需要什么？

- **A** 一个新账号
- **B** 一个不同的 system prompt 和不同的输入；只要姿态改变、且审查者对 diff 无写入权限，同一个模型可以扮演两个角色
- **C** 一个不同的模型
- **D** 不同的物理硬件

<details>
<summary>查看答案与解析</summary>

**答案**　B

纪律在于姿态和输入，而不在于模型身份。

</details>

## 4. Cloudflare 的 2026 审查架构长什么样？

- **A** 一个大审查者
- **B** 单个顺序 LLM
- **C** 在一个 Review Coordinator 下并行运行多达七个专家审查者并去重发现；只有协调者用顶级模型，专家用更便宜的档位
- **D** 轮转两个审查者

<details>
<summary>查看答案与解析</summary>

**答案**　C

Cloudflare 用专家 + 协调者架构在 30 天内跑了 131,246 次审查。

</details>

## 5. 下列哪一个不是本课列出的四种 LLM 评判偏差之一？

- **A** 位置偏差（A,B vs B,A 顺序不一致）
- **B** 冗长偏差（更长的输出得分更高）
- **C** 自我偏好（同一模型家族）
- **D** 向量局部性（vector locality）

<details>
<summary>查看答案与解析</summary>

**答案**　D

这四种是位置、冗长、自我偏好、权威；向量局部性不是其中之一。

</details>

## 6. 什么是校准集（calibration set）？

- **A** 一个 A/B 测试夹具
- **B** 10-20 个有已知正确裁决的历史任务收尾；每次 prompt 改动时重跑；若审查者一致性低于 80%，先修评分标准再上线
- **C** 一个新的训练语料
- **D** 一个向量索引

<details>
<summary>查看答案与解析</summary>

**答案**　B

校准集让审查者保持诚实；若一致性漂移，你修的是评分标准，不是数据。

</details>

## 7. 审查者的报告与工作台其余部分在哪里整合？

- **A** 它覆盖门
- **B** 它替换验证
- **C** 它只发给经理
- **D** 它打包进交接包（第 40 课）；人工审查从这份报告开始，而不是从一张白纸开始

<details>
<summary>查看答案与解析</summary>

**答案**　D

审查报告喂给交接，使下一个会话和人工审查者都从一份书面裁决开始。

</details>
