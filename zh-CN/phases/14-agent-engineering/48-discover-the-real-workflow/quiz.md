# 发现人们实际执行的工作流 · 自测

每题先选答案，再展开解析。

## 1. 为何从当前行为而非所需功能开始？

- **A** 这样避开用户
- **B** 真实工作流会揭示变通做法、交接、状态和约束
- **C** 这样保证生产就绪
- **D** 功能永远无用

<details>
<summary>查看答案与解析</summary>

**答案**　B

需求来自工作实际如何发生，而不只是人们提出什么。

</details>

## 2. 哪一项是最强的直接证据？

- **A** 路线图
- **B** 动作的系统追踪
- **C** 团队猜测
- **D** 用户描述通常发生什么

<details>
<summary>查看答案与解析</summary>

**答案**　B

追踪直接观察行为，而非报告或推断它。

</details>

## 3. 哪四个工作流接触面值得特别注意？

- **A** 模型、token、温度、prompt
- **B** 分支、提交、标签、发布
- **C** 颜色、字体、布局、动画
- **D** 摩擦、隐性状态、权限和例外

<details>
<summary>查看答案与解析</summary>

**答案**　D

这些接触面常包含真正的问题和风险。

</details>

## 4. 为何保留工作流变体？

- **A** 变体更容易编码
- **B** 所有用户相同
- **C** 这样不再需要证据
- **D** 平均值可能谁都描述不了，并抹去有效的角色或风险差异

<details>
<summary>查看答案与解析</summary>

**答案**　D

差异可能编码角色、策略、专业程度或遗留状态。

</details>

## 5. 直接证据比例传达什么？

- **A** 功能完整性
- **B** 部署成本
- **C** 多少工作流基于观察而非报告或推断
- **D** 模型准确率

<details>
<summary>查看答案与解析</summary>

**答案**　C

它让证据强度保持可见。

</details>

## 6. 什么是隐藏的工作流步骤？

- **A** 单元测试
- **B** CSS 过渡
- **C** 公开 API
- **D** 正式流程外由记忆、聊天或个人笔记承载的工作

<details>
<summary>查看答案与解析</summary>

**答案**　D

隐性状态常解释为何可见流程不完整。

</details>
