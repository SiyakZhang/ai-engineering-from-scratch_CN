# 把每次 agent 纠正变成系统改进 · 自测

每题先选答案，再展开解析。

## 1. 反复出现的 agent 纠正揭示什么？

- **A** 仅仅是模型薄弱
- **B** 跳过测试的理由
- **C** 需要更多聊天历史
- **D** 工作系统中缺失或薄弱的控制

<details>
<summary>查看答案与解析</summary>

**答案**　D

纠正是对缺失测试、边界、示例、工具或决定的观察。

</details>

## 2. 回归纠正应在哪一处变得持久？

- **A** 会议记录
- **B** 测试或评估
- **C** 更长的 prompt
- **D** 新模型

<details>
<summary>查看答案与解析</summary>

**答案**　B

可执行的证明可防止相同错误结果悄悄重现。

</details>

## 3. 为何在写规则前先找根因？

- **A** 这样避免全部复杂性
- **B** 症状可能来自不同的缺失控制
- **C** 规则需要引用
- **D** 这样不需要证据

<details>
<summary>查看答案与解析</summary>

**答案**　B

只针对症状的规则会在同一原因换一种形式出现时失效。

</details>

## 4. 一次性纠正何时值得永久控制？

- **A** 从不
- **B** 只在发布后
- **C** 复发或后果足以支撑持久复杂度时
- **D** 总是

<details>
<summary>查看答案与解析</summary>

**答案**　C

棘轮应保留有意义的判断，而非累积每个偏好。

</details>

## 5. 为何为提升后的控制生成指纹？

- **A** 在不丢失不同原因的前提下合并重复经验
- **B** 替代验证
- **C** 用于视觉设计
- **D** 隐藏所有权

<details>
<summary>查看答案与解析</summary>

**答案**　A

稳定标识可防止反复加入同一控制。

</details>

## 6. 为何每项控制都需要淘汰检查？

- **A** 所有规则每天过期
- **B** 测试无法持久
- **C** agent 不喜欢说明
- **D** 控制可能过时、冲突或被取代

<details>
<summary>查看答案与解析</summary>

**答案**　D

工作系统应保持最小且当前，而不是只累积策略。

</details>
