# 评审循环 · 自测

每题先选答案，再展开解析。

## 1. 为什么评审按五个固定维度打分，而不是返回一段自由文本？

- **A** 因为 reviser 只接受 JSON
- **B** 因为固定向量让 harness 能够逐维度检测跨轮次的退步
- **C** 因为模型无法可靠地生成段落
- **D** 因为 LaTeX 需要分数字段

<details>
<summary>查看答案与解析</summary>

**答案**　B

固定维度向量把评审变成了结构化数据，harness 可以跨轮次比较。自由文本的批评无法验证；向量让退步可见。

</details>

## 2. 循环在每轮结束时按什么顺序检查停止条件？

- **A** 高原 → 目标 → 预算
- **B** 预算 → 高原 → 目标
- **C** 看哪个先触发就随机打破平局
- **D** 目标 → 高原 → 预算

<details>
<summary>查看答案与解析</summary>

**答案**　D

目标达成优先（工作完成了）。然后是高原（不可能再有进步了）。然后是预算（硬性上限）。这个顺序让多个条件同时可触发时结果是确定的。

</details>

## 3. 为什么高原检测要求连续两轮持平，而不是一轮？

- **A** 因为仪表盘期望两个数据点
- **B** 因为 dataclass 需要一个列表
- **C** 因为即使确定性评分每轮的输出也会变化；一轮持平的信号不够强
- **D** 因为模型返回的是非确定性分数

<details>
<summary>查看答案与解析</summary>

**答案**　C

即使确定性评分器的输出也会因采纳了不同建议而逐轮变化。要求两轮持平能过滤掉这种噪声。

</details>

## 4. reviser 每轮接收什么作为输入？

- **A** 论文和 Suggestion 记录列表
- **B** 原始 LaTeX 源码
- **C** 包含分数的完整 Critique 对象
- **D** 模型生成的一段文字

<details>
<summary>查看答案与解析</summary>

**答案**　A

Reviser.__call__ 接受 (paper, suggestions)。每个 Suggestion 包含维度、目标 section 和一条编辑指令。reviser 看不到分数。这种分离让双方都可以独立替换。

</details>

## 5. trace 中每轮包含什么？

- **A** 模型 prompt 和 completion
- **B** 轮次编号、分数向量、均值、已应用的建议、判定结果
- **C** 仅收敛判定
- **D** 仅最终论文草稿

<details>
<summary>查看答案与解析</summary>

**答案**　B

trace 是每轮的事件日志。仪表盘把它渲染为分数随时间变化的图表；下一阶段读它来决定该分支是否值得保留。

</details>

## 6. 一个持续发出建议但从未提升任何分数的评审，最终会产生哪种终止判定？

- **A** plateau 或 budget，因为 harness 会捕捉到缺乏进步
- **B** 异常，因为循环崩溃了
- **C** converged，因为建议被采纳了
- **D** target，因为预算掩盖了这个 bug

<details>
<summary>查看答案与解析</summary>

**答案**　A

要么高原（连续两轮持平）要么预算（硬性上限）被触发。两种判定都能暴露这个 bug。循环永远不会默默成功。

</details>
