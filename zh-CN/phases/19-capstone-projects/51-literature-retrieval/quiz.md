## 1. 为什么检索客户端要分别跑一轮 BM25 和一轮引用图谱检索？

- **A** 因为 BM25 需要图谱来构建索引
- **B** 因为词汇匹配会漏掉用不同术语表述的基础论文，而图谱匹配会漏掉与种子论文没有引用关系的论文
- **C** 因为 mock API 要求这样做
- **D** 因为解析器不支持其他方式

<details>
<summary>查看答案与解析</summary>

**答案**　B

两种方式互补。词汇匹配覆盖共享术语的论文；图谱匹配覆盖有引用关系但措辞不同的论文。

</details>

## 2. 为什么引用图谱遍历的跳数上限是两跳？

- **A** 因为超过两跳后结果集往往偏离主题，淹没下游排序
- **B** 因为 BM25 只能打分两跳以内的论文
- **C** 因为 Python 递归限制不允许三跳
- **D** 因为语料库只存储了两层引用

<details>
<summary>查看答案与解析</summary>

**答案**　A

两跳是实际上限。在一个连通图上三跳会导致结果集爆炸，而且很少能带回更多相关论文。

</details>

## 3. 对于一个在每篇文档中都出现的词，idf 计算结果是什么？

- **A** 一个很大的正数
- **B** 负无穷
- **C** 未定义；BM25 实现会跳过它
- **D** 接近零的值

<details>
<summary>查看答案与解析</summary>

**答案**　D

当 df 等于 N 时，log 里的分子分母很接近，加 1 后保持非负但很小。处处出现的常见词贡献接近于零。

</details>

## 4. 合并步骤用哪个字段对两轮结果进行去重？

- **A** 稳定的论文 id
- **B** 论文标题文本
- **C** 年份加第一作者
- **D** BM25 分数桶

<details>
<summary>查看答案与解析</summary>

**答案**　A

论文 id 是稳定标识。标题和作者在不同版本间会重复，仅靠年份也有歧义。

</details>

## 5. 对于距离种子集两跳的论文，graph_score 返回什么值？

- **A** BM25 分数除以十
- **B** 零
- **C** 默认 1.0
- **D** 默认 0.3

<details>
<summary>查看答案与解析</summary>

**答案**　D

默认的图谱分数计划是：零跳 1.0，一跳 0.6，两跳 0.3，超过两跳为零。

</details>

## 6. 为什么语料库在 RetrievalClient 中一次性加载，而不是每次查询都重新获取？

- **A** 因为 BM25 索引和引用图谱在构造时一次性建好，之后跨查询复用
- **B** 因为解析器是全局的
- **C** 因为时效性评分需要它
- **D** 因为 mock API 每次调用都很慢

<details>
<summary>查看答案与解析</summary>

**答案**　A

索引构建是开销大的步骤。复用索引把这个成本分摊到客户端处理的每次查询上。

</details>
