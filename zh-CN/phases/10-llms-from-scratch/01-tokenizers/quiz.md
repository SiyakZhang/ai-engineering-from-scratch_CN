# 分词器：BPE、WordPiece、SentencePiece · 自测

每题先选答案，再展开解析。

## 1. 在 LLM 流水线中，tokenizer 的主要作用是什么？

- **A** 从文本中移除停用词
- **B** 把文本转换成模型能处理的整数序列
- **C** 在不同语言之间翻译文本
- **D** 压缩文本以便存储

<details>
<summary>查看答案与解析</summary>

**答案**　B

LLM 处理的是数字，而不是文本。tokenizer 把每个字符、单词和符号都转换成来自固定词表的整数 ID。这种转换并非中立的——它决定了模型如何「看见」语言。

</details>

## 2. BPE（字节对编码）是如何构建其词表的？

- **A** 随机给子串分配 ID
- **B** 对整个单词使用字典查找
- **C** 迭代地合并出现频率最高的相邻 token 对，直到达到目标词表大小
- **D** 只把文本拆分成单个字符

<details>
<summary>查看答案与解析</summary>

**答案**　C

BPE 从单个字节/字符开始，反复合并最常见的相邻对。'th' + 'e' 合并成 'the'。经过数千次合并后，常见单词成为单个 token，而罕见单词被拆成子词片段。

</details>

## 3. 为什么词表大小会在 LLM 设计中造成权衡？

- **A** 词表越大性能总是越好
- **B** 词表大小不影响模型性能
- **C** 词表越小总是越高效
- **D** 词表太小会产生长序列（计算量更大）；太大则会把 embedding 参数浪费在罕见 token 上

<details>
<summary>查看答案与解析</summary>

**答案**　D

小词表（例如字符级）意味着每个单词都是很多个 token，增加序列长度和计算量。大词表则把参数浪费在训练数据里很少出现的 token 上。大多数 LLM 使用 32K-100K 个 token。

</details>

## 4. 字节级回退（byte-level fallback）在分词中解决了什么问题？

- **A** 它加快了分词速度
- **B** 它确保任何输入（emoji、罕见文字、二进制数据）都能被编码而不产生「未知」token
- **C** 它提高了模型准确率
- **D** 它减小了词表大小

<details>
<summary>查看答案与解析</summary>

**答案**　B

有了字节级回退，tokenizer 可以对任何不在词表中的字符回退到原始字节值（共 256 种可能）。这保证了完整覆盖——任何输入都不会是「未知」。

</details>

## 5. tokenizer 如何影响 LLM 在非英语语言上的表现？

- **A** 在训练数据中代表性不足的语言会得到更差的 token 合并，导致每个单词需要更多 token，从而浪费上下文窗口
- **B** 非英语文本总是按字符分词
- **C** 分词不影响语言表现
- **D** tokenizer 对所有语言效果一样好

<details>
<summary>查看答案与解析</summary>

**答案**　A

BPE 的合并是从训练数据中学到的。如果日语文本只占语料的 5%，日语字符得到的合并就更少，每个单词需要比英语多 2-5 倍的 token。这实际上为非英语文本缩小了上下文窗口。

</details>
