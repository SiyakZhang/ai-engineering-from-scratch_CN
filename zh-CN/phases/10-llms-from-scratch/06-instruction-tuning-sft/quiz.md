# 指令微调（SFT） · 自测

每题先选答案，再展开解析。

## 1. 基础语言模型和指令微调模型之间的根本区别是什么？

- **A** 基础模型续写文本模式；指令微调模型遵循指令并回答问题
- **B** 指令微调模型更大，因为微调会新增参数，用来存储回答的方法
- **C** 基础模型更快，因为指令微调会加一道安全检查，生成每个 token 时都要运行
- **D** 两者架构不同：指令微调会新增一个输出头，把预测转换成答案

<details>
<summary>查看答案与解析</summary>

**答案**　A

用下一个 token 预测训练出的基础模型只是续写文本模式。问它一个问题，它可能生成更多问题。SFT 通过在（指令，回复）对上训练，教会它产生答案。

</details>

## 2. 在 SFT 中对非 assistant token 进行损失掩码（masking）的目的是什么？

- **A** 为了防止过拟合：随机遮住一部分 prompt token，类似预训练中的 dropout
- **B** 为了减少内存占用，因为被掩码的 token 在前向传播之前就从批次中移除了
- **C** 只训练模型生成回复，而不是记忆指令格式或 system prompt
- **D** 为了加快训练，因为反向传播会跳过所有损失被设为 0 的 token

<details>
<summary>查看答案与解析</summary>

**答案**　C

在 SFT 中，你希望模型学会如何回复，而不是如何重现指令。损失掩码把 system/user token 的损失设为 0，这样梯度只来自 assistant 的回复 token。

</details>

## 3. SFT 训练数据通常遵循什么格式？

- **A** 原始文本文档，和预训练数据类似，只是来源质量更高
- **B** 带有 system、user 和 assistant 角色的对话模板，角色由特殊 token 标记
- **C** 成对的优选回复和被拒回复，由人类选出更好的一个
- **D** 单条 prompt，每条都标有理想答案的 1 到 10 分评分

<details>
<summary>查看答案与解析</summary>

**答案**　B

SFT 数据使用结构化的对话格式：设定行为的 system prompt、一条 user 指令以及一条 assistant 回复。特殊 token 标记角色边界，使模型学到对话结构。

</details>

## 4. 为什么一个 SFT 模型可能在基准上困惑度更低，但对话质量更差？

- **A** SFT 数据太少，改变不了行为：几万条样本能改变基准数字，对话风格却保持原样
- **B** SFT 优化的是对训练样本的模式匹配，而不是人类所在意的细微质量判断——后者需要 RLHF/DPO
- **C** 模型太小：参数低于约 700 亿时，SFT 能提高基准分数，却永远无法改善对话
- **D** 基准不适合评估对话：困惑度在被掩码的指令 token 上计算，从未看到模型实际怎样回答

<details>
<summary>查看答案与解析</summary>

**答案**　B

SFT 教模型遵循格式并产生看似合理的回复。当存在多个有效选项时，它并不教模型哪个回复更好。人类偏好对齐（RLHF/DPO）弥补了这一缺口。

</details>

## 5. 有效的 SFT 通常需要多少高质量的指令-回复对？

- **A** 少于 100 条人工编写的样本
- **B** 数十亿条，和预训练一样多
- **C** 1 万到 10 万条高质量样本
- **D** 从网上抓取的数百万条样本

<details>
<summary>查看答案与解析</summary>

**答案**　C

SFT 在数据效率上出人意料。研究表明，1 万到 10 万条高质量样本（如 Alpaca 或 LIMA 数据集）就能有效教会指令遵循。质量远比数量重要。

</details>
