# MCP Registry 供应链：准入、漂移与回滚 · 自测

每题先选答案，再展开解析。

## 1. 在 MCP Registry 中成功发布，对生产网关意味着什么？

- **A** 最新版本应立即替换所有旧路由
- **B** 该服务器对每个主体都是安全的
- **C** 实时端点与已发布的包完全一致
- **D** 该记录已通过 Registry 发布控制，但仍需要本地运行时准入

<details>
<summary>查看答案与解析</summary>

**答案**　D

Registry 发布建立的是发布事实。制品、运行时、授权和本地审批检查仍然彼此独立。

</details>

## 2. 已验证命名空间为 com.example 时，哪种比较能拒绝 com.exampleevil/tool？

- **A** 在斜杠处分割并精确比较命名空间段
- **B** 搜索 example 子字符串
- **C** 信任 server.json 中写入的命名空间
- **D** 检查完整名称是否以 com.example 开头

<details>
<summary>查看答案与解析</summary>

**答案**　A

精确的分段比较保留命名空间边界，并使用受信验证器提供的权威信息。

</details>

## 3. 一个实时服务器新增了工具，但 Registry 记录和包坐标保持不变。哪项证据可以发现这一点？

- **A** 仅使用语义化版本字符串
- **B** 命名空间认证方式
- **C** 将新的归一化描述符摘要与已准入的工具集 pin 比较
- **D** Registry 发布时间戳

<details>
<summary>查看答案与解析</summary>

**答案**　C

实时描述符固定可发现发布元数据和包坐标无法显示的行为漂移。

</details>

## 4. 已准入的 Registry 版本从 active 变为 deprecated 时，应如何处理？

- **A** 删除所有证据，让客户端无法发现它
- **B** 从新路由中隔离它，并保留历史准入证据
- **C** 将已发布记录改写回 active
- **D** 忽略状态，因为包所有权已验证

<details>
<summary>查看答案与解析</summary>

**答案**　B

状态是运行输入。隔离会停止新的使用，而保留证据可支持审计和回滚分析。

</details>

## 5. 哪个目标符合自动回滚条件？

- **A** 先前已准入、按策略处于活动状态、健康且未隔离的 pin
- **B** 被标为 latest 的版本，即使它从未审查过
- **C** 包名熟悉但 Registry 已删除的版本
- **D** 名称排序在候选版本之前的任意版本

<details>
<summary>查看答案与解析</summary>

**答案**　A

回滚恢复的是已知可准入的路由，不会绕过当前状态、健康状况或隔离检查。

</details>

## 6. 为什么应将准入账本头锚定到独立信任域？

- **A** 本地哈希链能发现编辑，独立锚点则能发现完整的本地改写
- **B** 这样就不再需要制品摘要
- **C** 这样可将可变版本范围转为精确 pin
- **D** 这样发布者就能设置 Registry 管理的状态

<details>
<summary>查看答案与解析</summary>

**答案**　A

若攻击者能改写整个本地账本，他可以重新计算链条；外部签名或一次写入锚点能暴露这种改写。

</details>
