# 共指消解 · 自测

每题先选答案，再展开解析。

## 1. 共指消解的目标是什么？

- **A** 标注词性
- **B** 把代词翻译成名词
- **C** 抽取关系
- **D** 把所有指代同一现实世界实体的提及（命名、名词性、代词性）聚成一簇

<details>
<summary>查看答案与解析</summary>

**答案**　D

共指消解把所有指代同一实体的提及跨度聚成一簇。

</details>

## 2. 哪种表达是“名词性”（nominal）提及？

- **A** 像 'she' 这样的代词
- **B** 仅专有名词
- **C** 像 'the CEO' 或 'the company' 这样的名词短语
- **D** 一个动词

<details>
<summary>查看答案与解析</summary>

**答案**　C

名词性提及是像 'the company' 这样的名词短语；代词性提及是代词。

</details>

## 3. 现代（Lee 等, 2017）的共指架构是什么？

- **A** 端到端、基于跨度：枚举跨度，给提及打分，再给先行词概率打分并贪心聚类
- **B** 决策树
- **C** BM25 检索
- **D** 仅基于规则的句法分析

<details>
<summary>查看答案与解析</summary>

**答案**　A

端到端神经共指枚举跨度，并联合学习提及打分 + 先行词打分。

</details>

## 4. CoNLL F1 是对什么求平均？

- **A** MUC、B-cubed 和 CEAF-phi4 的 F1 分数
- **B** 跨语言的 F1
- **C** token 和跨度 F1
- **D** 精确率和召回率

<details>
<summary>查看答案与解析</summary>

**答案**　A

CoNLL F1 是 MUC、B-cubed 和 CEAF-phi4 指标的均值。

</details>

## 5. 什么是桥接照应（bridging anaphora）？

- **A** 没有先行词的代词
- **B** 出现在指称对象之前的代词
- **C** 一个误译
- **D** 一种隐式指代，例如 'the wheels' 暗指前文提到的某辆车的轮子

<details>
<summary>查看答案与解析</summary>

**答案**　D

桥接把一个提及链接到一个被暗示但未明说的“部分-整体”或相关实体。

</details>

## 6. 为什么仅靠 LLM 做共指在长文档上不可靠？

- **A** LLM 无法读取文本
- **B** 单次调用的 LLM 在 50+ 段落中会过度合并或悄悄丢掉提及；需要滑动窗口加合并
- **C** tokenizer 失败
- **D** 共指需要一个 CFG

<details>
<summary>查看答案与解析</summary>

**答案**　B

长文档 LLM 共指会退化；带跨窗口合并的滑动窗口可缓解。

</details>

## 7. 为什么在下游任务前要把共指簇并入 NER 结果？

- **A** Wikidata 所要求
- **B** 让下游任务看到每簇一个实体，而非每个表面提及一个，从而大幅提升覆盖率
- **C** 为了增加 token 数
- **D** 降低延迟

<details>
<summary>查看答案与解析</summary>

**答案**　B

不合并的话，NER 会把每个表面形式分开计数，漏掉 60-80% 的实体提及。

</details>

## 8. 为什么硬编码的性别规则是共指系统中的一个脆弱点？

- **A** 它们无法使用词性标签
- **B** 它们在非二元指称对象、组织和动物上会出错；学习型打分更稳健
- **C** 它们需要 GPU
- **D** 它们跑得太快

<details>
<summary>查看答案与解析</summary>

**答案**　B

性别启发式在人口构成多样的文本上会失败；更偏好学习型模型。

</details>
