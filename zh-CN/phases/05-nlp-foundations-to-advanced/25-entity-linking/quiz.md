# 实体链接与消歧 · 自测

每题先选答案，再展开解析。

## 1. 实体链接在 NER 之上增加了什么？

- **A** 情感极性
- **B** 翻译
- **C** 词性标签
- **D** 它把每个检测到的提及映射到知识库（Wikidata、Wikipedia 或领域 KB）中的唯一条目

<details>
<summary>查看答案与解析</summary>

**答案**　D

实体链接把一个提及转为规范的 KB id，在同名实体之间消歧。

</details>

## 2. 实体链接的两个主要子任务是什么？

- **A** 词性标注和词形还原
- **B** 分词和句法分析
- **C** 候选生成（可能的 KB 条目的候选清单）和消歧（结合上下文挑出正确的那个）
- **D** 嵌入和聚类

<details>
<summary>查看答案与解析</summary>

**答案**　C

实体链接分解为先提出候选，再按上下文契合度对它们排序。

</details>

## 3. 为什么必须把提及召回率与消歧准确率一并报告？

- **A** 消歧无法从缺失的候选中恢复；整个流水线受候选生成召回率的限制
- **B** 召回率替代精确率
- **C** spaCy 要求召回率
- **D** 提及召回率是 GDPR 强制的

<details>
<summary>查看答案与解析</summary>

**答案**　A

如果候选中漏掉了正确实体，再好的消歧器也无法修正；召回率限定了流水线质量的下限。

</details>

## 4. GENRE 如何执行实体链接？

- **A** 通过 BM25
- **B** 通过 PageRank
- **C** 通过计算 TF-IDF
- **D** 在有效 KB id 的字典树（trie）上做受约束解码，逐 token 解码出实体的规范名称

<details>
<summary>查看答案与解析</summary>

**答案**　D

GENRE 用受约束解码生成规范 KB 名称，以保证产生一个有效的 id。

</details>

## 5. 实体链接中的 NIL 处理是什么？

- **A** 跳过每一个提及
- **B** 返回整个候选列表
- **C** 当没有候选是真正匹配时（新兴实体、冷门人物），预测一个“不在 KB 中”的标签
- **D** 把输入转小写

<details>
<summary>查看答案与解析</summary>

**答案**　C

NIL 预测可防止对 KB 未覆盖的实体猜测出错误的 KB id。

</details>

## 6. 为什么流行度偏差会损害专业领域的实体链接？

- **A** 流行度有助于召回
- **B** 它只偏向更老的实体
- **C** 在网络数据上训练的模型会过度预测高频实体（例如把篮球的 Jordan 预测在机器学习研究者 Michael I. Jordan 之上）
- **D** 流行度移除了 NIL

<details>
<summary>查看答案与解析</summary>

**答案**　C

流行度先验使预测偏离不常见、领域特定的同名冲突。

</details>

## 7. 2026 年一个稳妥的 LLM 实体链接模式是什么？

- **A** 跳过候选生成
- **B** 只 prompt “找出实体”
- **C** 自由形式生成
- **D** 提供一个候选列表，并使用受约束的 JSON 输出，使 LLM 只能从有效 KB id 中选择

<details>
<summary>查看答案与解析</summary>

**答案**　D

把 LLM 约束到一个有效候选列表，可防止编造 KB id，并使输出保持可查询。

</details>

## 8. 为什么 NER 的提及边界必须精确，实体链接才能奏效？

- **A** 边界改变分词
- **B** 边界精度只影响 NER 指标，不影响实体链接候选质量
- **C** 边界错误会传播：'Bank of America' 被裁成 'Bank' 会带出错误候选，拖垮实体链接召回率
- **D** 边界破坏 Wikipedia 查找

<details>
<summary>查看答案与解析</summary>

**答案**　C

边界错误的提及会检索到错误的别名集，把错误传播到消歧环节。

</details>
