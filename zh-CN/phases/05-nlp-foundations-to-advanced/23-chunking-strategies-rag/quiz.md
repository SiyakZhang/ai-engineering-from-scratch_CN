## 1. 为什么在 RAG 中分块策略和嵌入模型同等重要？

- **A** FAISS 要求分块
- **B** 更小的块训练更快
- **C** 块边界决定了答案是否可被检索到；糟糕的块会击败任何嵌入
- **D** 分块缩小了模型

<details>
<summary>查看答案与解析</summary>

**答案**　C

Vectara 2025 年的研究表明，分块质量对检索质量的影响与嵌入模型相当甚至更大。

</details>

## 2. LangChain 的 RecursiveCharacterTextSplitter 按什么顺序尝试切分？

- **A** 先尝试在段落分隔处切，然后换行符，再句子边界，最后空格
- **B** 总是在第 N 个字符处切分
- **C** 仅在空白处切分
- **D** 在 token ID 上切分

<details>
<summary>查看答案与解析</summary>

**答案**　A

递归切分按 段落 -> 换行 -> 句子 -> 空格 逐级回退，以保留结构。

</details>

## 3. 为什么父文档模式能提升答案质量？

- **A** 它避免了分词
- **B** 它移除了嵌入
- **C** 子块给出精确检索；返回更大的父块保留了阅读器所需的周边上下文
- **D** 它消耗更少的 GPU 周期

<details>
<summary>查看答案与解析</summary>

**答案**　C

按小的子块检索以获得精确度，再扩展到父块以获取上下文。

</details>

## 4. Anthropic 的“上下文检索”（contextual retrieval）在索引前给每个块加了什么？

- **A** 一段由 LLM 生成的 50-100 词摘要，把该块置于文档的整体上下文中
- **B** 一个词性标签
- **C** 随机噪声
- **D** 一个语言代码

<details>
<summary>查看答案与解析</summary>

**答案**　A

上下文检索在每个块前加一段 LLM 写的定位摘要；带来约 35-50% 的召回提升。

</details>

## 5. 2026 年的哪个发现与关于块重叠（overlap）的传统观念相悖？

- **A** 重叠只对上下文检索有帮助
- **B** BM25 需要重叠
- **C** 重叠应为 50%
- **D** 2026 年的实证基准显示，重叠往往带不来可测量的收益，却让索引成本翻倍

<details>
<summary>查看答案与解析</summary>

**答案**　D

较新的研究（在 NQ 上用 SPLADE+Mistral）显示块重叠很少有帮助，反而膨胀索引大小。

</details>

## 6. NVIDIA 的 2026 基准把哪种块大小与事实型查询（factoid）相关联？

- **A** 2048-4096 个 token
- **B** 64 个 token
- **C** 大约 256-512 个 token
- **D** 8192 个 token

<details>
<summary>查看答案与解析</summary>

**答案**　C

事实型查询受益于更小的块（256-512 token），它们能聚集答案信号。

</details>

## 7. 使用语义分块时，为什么最小 token 下限很重要？

- **A** 没有下限，语义分块可能产生只有 40 个 token 的微小碎片，损害检索
- **B** BERT 所要求
- **C** 下限防止重叠
- **D** 下限加速推理

<details>
<summary>查看答案与解析</summary>

**答案**　A

语义分块器可能过度切分；强制一个最小尺寸可防止低信号碎片。

</details>

## 8. “后期分块”（late chunking）与传统分块有什么不同？

- **A** 完全跳过分块
- **B** 先在 token 级别嵌入整篇文档，再把 token 嵌入池化成块向量，以保留跨块上下文
- **C** 改用 BM25
- **D** 在检索之后分块

<details>
<summary>查看答案与解析</summary>

**答案**　B

后期分块先嵌入后池化，保留了跨块边界的上下文交互。

</details>
