# 用 LoRA 和 QLoRA 微调 · 自测

每题先选答案，再展开解析。

## 1. LoRA（低秩适配，Low-Rank Adaptation）背后的核心洞见是什么？

- **A** 微调只需要最后一层
- **B** 大多数权重无关紧要
- **C** 微调时的权重更新具有低内在秩，因此可以用两个小矩阵来近似，而不必更新整个权重矩阵
- **D** 更小的模型总是更好

<details>
<summary>查看答案与解析</summary>

**答案**　C

Aghajanyan 等人证明微调的更新位于一个低维子空间中。LoRA 利用这一点，把更新表示为 W + BA，其中 B（d x r）和 A（r x d）的秩 r 很小，通常 8-64。

</details>

## 2. 相比对一个 8B 模型做全量微调，LoRA 能节省多少内存？

- **A** 不节省
- **B** 减少 50%
- **C** 通过在保持基座权重冻结的同时训练不到 1% 的参数，从约 56GB 降到约 6GB
- **D** 只节省磁盘空间

<details>
<summary>查看答案与解析</summary>

**答案**　C

全量微调需要为全部 8B 参数保存梯度和优化器状态（约 56GB）。LoRA 冻结基座权重，只训练适配器矩阵（秩 16 时约 8000 万参数），总共只需约 6GB。

</details>

## 3. 什么是 QLoRA？

- **A** 一种不同的微调算法
- **B** 更快版本的 LoRA
- **C** 量化版 LoRA：基座模型以 4 位精度加载，而 LoRA 适配器以 16 位训练，结合两种技术的内存节省
- **D** 应用于量化激活值的 LoRA

<details>
<summary>查看答案与解析</summary>

**答案**　C

QLoRA（Dettmers 等人）以 4 位（NF4 量化）加载冻结的基座模型，同时以 FP16/BF16 训练 LoRA 适配器。这使得在一张 6GB VRAM 的消费级 GPU 上微调 7B 模型成为可能。

</details>

## 4. LoRA 中的「秩」参数（r）控制什么？

- **A** 学习率
- **B** 要微调的层数
- **C** 训练轮数
- **D** 适配器的容量：秩越高能捕捉越复杂的适配，但使用更多参数和内存

<details>
<summary>查看答案与解析</summary>

**答案**　D

秩 r 决定适配器矩阵 A（r x d）和 B（d x r）的大小。秩 4 训练极少的参数（快、省）。秩 64 训练更多参数（表达力更强）。大多数任务在秩 8-32 下效果良好。

</details>

## 5. 当你把 LoRA 权重合并回基座模型时会发生什么？

- **A** 模型需要重新训练
- **B** 适配器矩阵被加到基座权重上（W_merged = W_base + B*A），产出一个没有推理开销的标准模型
- **C** 无法合并
- **D** 模型变大

<details>
<summary>查看答案与解析</summary>

**答案**　B

由于 LoRA 是 W_base + B*A，你可以一次性计算 B*A 并永久加到 W_base 上。合并后的模型与原始模型有相同的架构和推理速度，没有适配器开销。

</details>
