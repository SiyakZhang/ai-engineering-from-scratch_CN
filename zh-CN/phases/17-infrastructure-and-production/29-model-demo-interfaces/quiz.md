## 1. 页面已经在文本输入框上通过 maxlength 属性限制了长度。为什么服务端必须再次校验长度？

- **A** 浏览器只有在整个模型前向推理全部结束后才会触发 maxlength 截断
- **B** 任何客户端都可以绕过前端页面直接向接口发送原生 HTTP 请求
- **C** 除非用户关闭了 JavaScript，否则浏览器通常会忽略文本框上的 maxlength 属性
- **D** maxlength 属性统计的是字节数而非字符数，因此容易放行过多字符

<details>
<summary>查看答案与解析</summary>

**答案**　B

浏览器端校验只对守规矩的正常用户有帮助。任何自动化脚本或 curl 命令都可以脱离前端页面直接发送任意请求体，因此服务端必须无条件重复全部校验。

</details>

## 2. 本课中定义的 Demo 接口契约包含哪三个组成部分？

- **A** 登录鉴权页、订单支付页与最终结果展示页
- **B** 前端界面（Frontend）、后端服务（Backend）与数据库层（Database）
- **C** 提示词（Prompt）、模型权重（Weights）与 GPU 服务器
- **D** 输入（Input）、模型调用（Model call）与输出（Output）

<details>
<summary>查看答案与解析</summary>

**答案**　D

一个完备的 Demo 契约由输入、模型调用和输出三部分构成。Demo 必须对每个组成部分设置严格的边界限制，而错误响应同样属于输出的一部分。

</details>

## 3. 为什么 Demo 页面发送 POST 请求并使用 fetch() 读取流，而不是直接使用浏览器自带的 EventSource？

- **A** fetch() 跳过了全部响应头因此能大幅降低首字到达延迟（TTFT）
- **B** EventSource 在规范上无法解析服务端下发的 text/event-stream 标准格式
- **C** EventSource 仅支持发送 GET 请求，导致用户输入内容不得不拼接暴露在 URL 中
- **D** Python http.server 处理器在底层仅支持在响应 POST 请求时输出流数据

<details>
<summary>查看答案与解析</summary>

**答案**　C

EventSource 规范仅支持发起 GET 请求。GET 请求会将用户输入暴露在 URL 中，导致各级 Web 反向代理和网关在访问日志中全量打印用户隐私内容。

</details>

## 4. 本课构建的 Demo 会在请求访问日志中记录什么？

- **A** 包含查询参数的完整请求行以及客户端的明文原始 IP 地址
- **B** 请求路由、状态码、延迟耗时、输入字符长度以及客户端的带盐哈希
- **C** 用户输入的原始文本和模型生成的完整文本，以便审查人员进行重放测试
- **D** 每个失败请求的完整堆栈追踪信息，包含内部代码文件路径与行号

<details>
<summary>查看答案与解析</summary>

**答案**　B

日志中绝不记录用户输入的文本内容，也不保留明文客户端 IP。带盐哈希允许系统在不持久化存储敏感 IP 的前提下精准统计各客户端的请求频次。

</details>

## 5. 服务端在已经下发了 HTTP 200 状态行和三个 token 事件后，模型内部突然崩溃报错。Demo 会如何处理？

- **A** 它将 HTTP 状态行修改为 500 并重新下发一套响应头
- **B** 它直接静默掐断 TCP 连接，让浏览器端自行等待超时
- **C** 它在现有的事件流中推送一个 error 事件，由前端页面负责将其捕获展示
- **D** 它在后台自动重试模型调用并在无感知的情况下静默追加新 token

<details>
<summary>查看答案与解析</summary>

**答案**　C

由于 HTTP 状态行在流式传输初期已经下发给客户端，协议层面无法再次更改状态码。因此必须在流内部下发携带错误码、说明与提示建议的结构化 error 事件。

</details>

## 6. 有一百个并发客户端，每个客户端的请求频率都没有突破单客户端限流阈值。哪项控制措施能防止他们耗尽模型总调用预算？

- **A** 为每个客户端配置更大容量的令牌桶，并提高令牌每秒补充速率
- **B** 下发仅允许单条内联哈希脚本运行的 Content-Security-Policy 响应头
- **C** 在页面 HTML 表单的文本区域上设置更小的 maxlength 属性值
- **D** 设置统计全量客户端累计调用总和的每日全局使用量上限（Usage cap）

<details>
<summary>查看答案与解析</summary>

**答案**　D

单客户端限流只能约束单个访客的滥用，无法约束宏观总量。每日使用量上限对所有客户端的调用总和进行全局计数，一旦达标便熔断拒绝后续请求。

</details>
